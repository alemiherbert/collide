# Collide — rebar clash detection, validation and safe resolution for Revit

Collide finds reinforcement conflicts in Revit models as you model, tells genuine defects apart from intentional
contacts, checks detailing against configurable and traceable rules, and proposes — or, only where explicitly
permitted, applies — corrections that are re-validated before and after every change.

> **Verification status.** The engine, live-monitoring pipeline and pane view model are fully unit-tested on
> synthetic models (105 tests). The Revit add-in **compiles** for Revit 2025, 2026 and 2027 against the Revit API
> reference assemblies, but it has **not yet been run inside Revit**. Nothing in this repository is evidence of
> real Revit API behaviour. See [docs/READINESS-REPORT.md](docs/READINESS-REPORT.md) and
> [docs/REVIT-INTEGRATION-TEST-PLAN.md](docs/REVIT-INTEGRATION-TEST-PLAN.md).

## What it does

| Area | Capability |
|---|---|
| Rebar–rebar | Physical clashes of real bar solids (not centrelines, not bounding boxes), duplicates, collinear overlaps, joint / slab-opening / wall-opening / foundation-starter / stirrup–longitudinal / hook-bend / coupler conflicts, unclassified contacts |
| Rebar–concrete | Bars outside all concrete, unintended host penetration, bars through openings/recesses, prohibited zones, cover to exposed faces and to openings (concealed faces from Revit cover settings) |
| Constructability | Clear spacing and aggregate passage, local congestion and beam–column joint congestion |
| Detailing (separate from geometry) | Lap length and geometry, declared or inferred anchorage, bend diameters, hook angle/extension, transverse spacing and confinement zones, maximum bar spacing, permitted diameters/shapes, set/mark consistency |
| Classification | Category, subtype, severity, confirmed / suspected / warning / indeterminate status, confidence, engineering-review flag, auto-resolution eligibility, recommended action, rule and source |
| Resolution | Minimal translations within placement tolerances (single bar, split, local re-spacing that keeps the bar count), hard constraints, neighbourhood re-validation, 11 named safety invariants, ranking, ambiguity detection, approval workflow, transactional execution with verified rollback, revert, audit trail |
| Live monitoring | `DocumentChanged` → id-only notifications → debounce → external-event extraction → incremental analysis on a background thread → dockable pane, with cancellation of obsolete work, stale/new/resolved tracking, pause/resume, scopes and full scans |
| Reporting | JSON (machine-readable) and Markdown (human-readable) reports with summary, issues, resolution outcomes, before/after measurements, correction and rollback history, audit and performance |

Missing design information never passes silently: required checks without an applicable rule or input are reported
as **indeterminate**, and compliance findings against rules that are not engineer-verified are reported as
**suspected**, never confirmed.

## Build and test

Requirements: .NET SDK 10.0.1xx (it builds the .NET 8 and .NET 10 targets and contains the WPF build tasks).
Building the add-in on Linux/macOS works (`EnableWindowsTargeting` is set automatically); running it needs Revit on Windows.

```bash
# Engine, view models and all tests (any OS)
dotnet test Collide.slnx -c Debug.R26

# Add-in for each supported Revit version (configuration suffix selects the Revit version)
dotnet build src/Collide.Revit -c Release.R25
dotnet build src/Collide.Revit -c Release.R26
dotnet build src/Collide.Revit -c Release.R27

# Regenerate the example reports
dotnet run --project samples/Collide.Samples -c Release.R26 -- .
```

On Windows, building `src/Collide.Revit` deploys the add-in to `%APPDATA%\Autodesk\Revit\Addins\<year>\` through the
Nice3point SDK (`DeployAddin`), together with `Collide.addin`.

## Using it in Revit (once validated there)

1. Put a project rule file next to the model as `<model>.collide.json` or `collide.rules.json`
   (or `%APPDATA%\Collide\collide.rules.json`, or set `COLLIDE_RULES`). Start from
   `samples/rules/example-project-rules.json` and replace every placeholder value with your project's requirements.
   Without a rule file, geometric clashes are still detected and compliance checks are reported as indeterminate.
2. Open the **Rebar clashes** pane from the **Collide** ribbon panel. Monitoring starts when a project opens; the pane
   refreshes automatically as you model.
3. Select an issue to zoom to it, select its elements, or inspect proposed corrections. Applying a correction is an
   explicit engineering approval; the change runs in one Revit transaction and is re-validated by the live monitor.
4. **Resolve** plans corrections for all eligible issues and applies only what the rules' `resolution.mode` permits
   (`ProposeOnly` by default — nothing is applied). **Export Report** writes JSON and Markdown reports next to the model.

Optional instance parameters on rebar: `Collide Layer` (layer label used by intentional-contact rules, e.g. `B1`, `T2`)
and `Collide Role` (overrides the inferred role, e.g. `OpeningTrimmer`, `Starter`).

## Safety controls (summary)

* Detection never modifies the model. Live monitoring never modifies the model; it cannot call the resolution engine.
* Corrections are rigid translations only, within explicit placement-tolerance rules; bars are never deleted, resized,
  shortened or reshaped, and laps/anchorage are never reduced (invariants INV-03 and INV-06).
* Automatic application requires `resolution.mode: ApplyUnambiguous`, a valid and verifiable candidate within the
  auto-apply limit, and a clear score margin over alternatives. Everything else is presented for approval.
* Every candidate is re-analysed with its neighbourhood before and after, and must pass all invariants; the executor
  re-checks the **actual** post-state read back from the model before committing and rolls back otherwise, then
  verifies the rollback.
* Stale preconditions (geometry hashes), re-entrancy guards, an idempotent ledger and exact revert records prevent
  double application and allow undoing corrections. Every step is in the audit log (JSON lines in Revit).

## Merging into Tekton

The layering mirrors Tekton's ports-and-adapters structure and conventions (Nice3point SDK 6.2.3, `Debug/Release.R25–R27`,
Serilog 4.4.0, CommunityToolkit.Mvvm 8.4.2, xunit 2.9.3, `Microsoft.Extensions` avoided in the engine). Suggested mapping:
`Collide.Core` → a new Revit-free `Tekton.Clash` project (or a Revit-free folder in `Tekton.Core`, like `Licensing/`);
`Collide.Presentation` → `Tekton.UI` view models; `Collide.Revit/Integration` → `Tekton.RevitAdapter`;
`Collide.Revit/Commands` → `Tekton.Commands`; `Collide.Revit/Application` wiring → `Tekton.Application`.
Tekton's per-version NuGet lock files are not yet generated for these projects.
